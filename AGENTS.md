# website (openOODA) — Public Documentation & Static Site Generator

Public source for [https://openooda.org](https://openooda.org) (`@openOODA`), served via
GitHub Pages from `docs/` (the sealed webroot). **v2.5.0** ships the canonical
4-organization architecture: `@openOODA` (4 platform + `.github`), `@openOODA-core`
(`15`), `@openOODA-system` (`37`), `@openOODA-apps` (`18`) = `70` product packages,
`78` repositories total. The repository is a pure `.oo` conformance surface over the
static site: every build/test proves the shipped tree is self-contained,
reference-complete, and telemetry-free.

## Zero-Telemetry Invariant (privacy.md Law 1)

`cards/privacy.md` Law 1 seals `RIGHT_ZERO_TELEMETRY` (Rights bit 128) on every
capability register — the public site honors the same law in the webroot:

1. **Zero third-party beacon hosts** in any shipped `.html`/`.js`/`.css`/`.svg` page:
   `cloudflareinsights.com`, `google-analytics`, `googletagmanager.com`, `mixpanel.com`,
   `sentry.io`, `telemetry_upload` are refused (detector needles stay split, matching
   `ooda-verify` Black Hat `telemetry_beacons`).
2. **Zero remote subresource loads**: `src=` (double- and single-quoted), `<link href=>`,
   and `url()` fetches must resolve locally under `docs/` — `<a href="https://…">` stays
   user-initiated navigation, never a fetch.
3. **Fail-closed enforcement**: `core/site_check.oo` (`site_beacon_hits`,
   `site_remote_refs`, `site_telemetry_free`, `site_tree_free`, `site_repo_ok`),
   `tests/test_refusal.oo` (8 telemetry refusal fixtures), `make site-gate`, both CI
   gates, and `ooda-verify black` (`telemetry_beacons=0` required for `quorum_mask=255`).

## Architecture (8-entry root)

```

  site_check.oo   refs/anchors/integrity/zero-telemetry fold over docs/

            install.sh, .nojekyll — no build step, no remote subresources)
tests/
  test_functional.oo   8 positive assertions over the shipped tree
  test_refusal.oo      14 negative assertions (dead refs, traversal, telemetry)
```

`cli/main.oo` is the lone entry page (`bin/website`); `tests/` is the lean 2-file
suite (0 source-grepping); `.github/workflows/{ci,deploy}.yml` replay the site gate
on checkout and before Pages deploy.

## Repository Completion Tracker

The landing page carries a live census of all `78` repositories, generated by
`.github/scripts/tracker.sh` — never hand-edited, so the page cannot drift from the
repositories it describes. The generator rewrites the block between
`<!-- TRACKER:BEGIN -->` and `<!-- TRACKER:END -->`, and rewrites every
`<span data-ver="org/repo">` version claim, so a version printed on the page always
matches that repository's latest release tag.

Each repository is scored on five gates — `VERSIONED`, `CITED`, `GREEN`, `SHIPPING`,
`CLEAN` — and the tier is decided by the **first gate that fails**, so a repository
is never credited for a later gate while an earlier one is red. Tiers: `COMPLETE`,
`OPEN WORK`, `STALE`, `CI RED`, `UNGATED`, `UNRELEASED`.

Every column is a directly observed fact rather than an inference. `ATTESTED`
compares the repository's latest release tag against the signed package index in
`@openOODA/catalog` — `SIGNED` when the catalog attests that exact release,
`DRIFT` when the repository has shipped ahead of the catalog. The release hub
owns that index: `sync-hub` records what each package declares at the commit it
built, rewrites the index from those values and re-signs it, so the registry
tracks the source rather than drifting behind it. `CAPS` is the
capability set the catalog records for the package. A matrix above the table rolls
the same facts up per layer.

**CI/CD is gated in `@openOODA` only** — that is the one organization that carries
CI/CD gates, and the other three ship without them. `CITED` and `GREEN` therefore do
not apply outside `@openOODA`, and a repository only counts as gated when it actually
carries a CI workflow file, so a verdict left behind by a removed workflow never
counts against it.

The webroot stays static: the tracker is rendered into the HTML at generation time and
the browser only ever reads local files, so no remote subresource load is introduced. and before Pages deploy.

## Verification Gates

```sh
make build    # ooda-compiler build cli/main.oo -> bin/website + dist/website
make test     # functional 8/8 + refusal 14/14 + check gate + about card (PATH=/nonexistent)
make verify   # line-cap, file-law, academy, density, vocab, shape, link-law, check, site-gate
make assets   # stamp a content hash onto every asset reference (see below)
~/.openooda/bin/ooda-verify cycle .
# required: cycle=PASS quorum_mask=255 telemetry_beacons=0
```

## Asset References Carry a Content Hash

GitHub Pages serves the page itself with a ten-minute cache and its assets
with a four-hour one, and the edge keeps both. Without a stamp, a deploy
publishes new HTML that can still be paired with the previous release's CSS
and JavaScript — a layout fix that sits on the server and never reaches a
browser. `make assets` puts `?v=<hash>` on every stylesheet and script
reference; `make assets --check` fails when the committed page no longer
matches the assets on disk, and CI runs it on every push. The reference
checks in the site gate and in `core/site_check.oo` resolve the file a
reference points at, so they cut the query before looking for it.

## Power-of-2 Shape Ladder & .oo Rules

`1` stmt/line & link-count 1 · `2`-file tests suite · `4` max nesting & 4-Axis review
(`ooda-verify` + semantics + native binary + ecosystem) · `8` files/dir, fns/file, params/fn,
root entries · `16` min lines/file · `32` caps & 32-char names · `64` lines/fn ·
`128` chars/line · `256` lines/file. Relative string imports only; no `if`/`while`
parens; no struct trailing commas; Academy header on every `.oo` page; always reuse
`ooda-standard` (`str.oo`, `sec/hash/sha256.oo`, `app/ui/ootheme.oo`) — never duplicate helpers.
