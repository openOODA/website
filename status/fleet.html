How This Board Updates

The board is a static page over generated JSON. The driver reads the tick state file and alert spool read-only and writes the data files (dogfood law — pure .oo, no shell): 

export OODA_COMPILER=/Projects/openOODA-core/oodac/bin/oodac.real
export OODA_NO_JAIL=1 OO_LIST_AMBIENT_QUOTA=8589934592
$OODA_COMPILER build -o /tmp/fleet-refresh src/fleet_refresh.oo
/tmp/fleet-refresh /path/.fleet-state.txt /path/.fleet-alerts \
  status/fleet.json status/fleet_history.jsonl

All four args are optional and default to the soak-era paths — /Projects/openOODA/.fleet-state.txt, /Projects/openOODA/.fleet-alerts, status/fleet.json, status/fleet_history.jsonl. At fleettick cutover only the arg paths change; the JSON contract and this page stay identical. History is tick-grain, sig-deduped, pruned to 1008 lines (7 days at 600s cadence); the repo sparklines render the last 24 ticks. A missing or unreadable state file fails closed — the refresh exits nonzero and never fabricates a healthy fleet.
