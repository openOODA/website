openOODA MCP Server — Preview

This is a preview showing what the mcp/ repo's docs/ look like when pulled into the website. The 4 .oot files below are the source-of-truth documents at openOODA/mcp/docs/: MCP_SETUP.oot, TOOLS.oot, protocol.oot, client_config.oot. ANCHOR.oo is the import-only index.

MCP_SETUP.oot — Setup

File: ooda/mcp/docs/MCP_SETUP.oot

The openOODA MCP (Model Context Protocol) server is a pure-.oo self-hosted MCP server. It speaks MCP protocol version 2024-11-05 over stdio (JSON-RPC 2.0 framed) and provides tools/list, tools/call, resources/list, resources/read, prompts/list, prompts/get, and a ping health probe.

The server is one of seven openOODA subsystems. It is a transport-only adapter: it parses JSON-RPC envelopes, runs an OODA dispatch loop, and emits framed responses. All semantic logic lives in the engine sub-modules under engine/.

Installation

The MCP server ships as part of the mcp package. Install the ooda toolchain, then add the mcp package to your project:

# 1. install the ooda toolchain (one-time)
oodaup install ooda@2.10.0

# 2. add the mcp package to your project
oodaup add mcp@0.5.0

# 3. verify the install
ooda mcp --help

The mcp package declares its compatibility range in VERSION:

mcp=0.5.0
ooda=2.10.0
ooda_max=2.99.0
oodac=2.10.0
std=2.10.0
api_surface=7

The mcp package refuses to run if the installed ooda toolchain is outside the declared range.

Environment variables

The server reads one environment variable:

NamePurposeDefault
OODACODEXOverride the path to the orientation codex (LLMS.oot)repo-relative path

The codex override is resolved under &EnvCap. No other environment variables are read.

Launching the server

The server binary has two subcommands: mcp (run the server) and mcp-merge (inject the ooda entry into an agent-tool JSON config).

Run the server in stdio mode (the editor case):

ooda mcp                # equivalent to: ooda mcp --stdio
ooda mcp --stdio        # explicit stdio flag

Run the server in one-shot file mode (a single batch read from a file, then exit):

ooda mcp --file path/to/request.txt

Run the server over a Unix socket:

ooda mcp --socket /tmp/ooda-mcp.sock

Inject the openOODA entry into an MCP client config (idempotent):

ooda mcp-merge ~/.config/openooda/agent-config.json

Exit codes for mcp-merge: 0 = no-op (already present), 1 = written, 2 = error.

Transport

The server uses one of three transports, selected at launch:

  1. stdio (default). The server reads the full stdin chunk, processes it, and writes framed responses to stdout. This is the standard MCP transport for editor integrations.
  2. file. The server reads one request from the given file path under &FsReadCap, processes it, and exits. Use this for batch jobs and CI smoke tests.
  3. socket. The server binds a Unix-domain socket under &BindCap and accepts connections.

All three transports use the same JSON-RPC 2.0 framing.

JSON-RPC 2.0 framing

The server uses LSP-style Content-Length framing on stdio. Each message is one HTTP-style header followed by a JSON body:

Content-Length: 123\r\n
\r\n
{"jsonrpc":"2.0","id":1,"method":"initialize","params":{...}}

The header is mandatory. Raw JSON objects without the Content-Length header are also accepted by the file transport, but stdio clients should always emit the header.

MCP vs LSP

The openOODA polyrepo ships both an MCP server and an LSP server. The two share framing but differ in semantics:

MCP (this server)LSP
PurposeTool use for AI agentsEditor-state for IDEs
CallerLLM agentCode editor
Methodstools/list, tools/call, resources/*, prompts/*textDocument/*, workspace/*, completion, hover
StatePer-request (session)Long-lived (open documents)
FramingJSON-RPC 2.0 + Content-LengthJSON-RPC 2.0 + Content-Length
DispatchOODA: Orient → Decide → ActLSP: server state machine
Capabilities14 cap tokensNone

MCP is request-response for tool use. LSP is editor-state-driven.

TOOLS.oot — Tool Catalog

File: ooda/mcp/docs/TOOLS.oot

The MCP server exposes 23 typed tools under tools/call. Each tool has a name, a one-line description, an input schema (JSON Schema fragment), and a requiresCap bitmask. Tools that read files need FsReadCap; tools that write need FsWriteCap. A requiresCap of 0 means the tool is callable with the default session cap.

All tool results are wrapped in the standard MCP content envelope:

{"content":[{"type":"text","text":"<json-string-payload>"}]}

The payload is a JSON string. Clients parse the inner text field to recover the typed result.

Capability Reference

The MCP server enforces a 14-bit capability token system. Each tool advertises its required cap as a bitmask in the tools/list response. A requiresCap of 0 means the default session cap is enough. Non-zero values mean the caller must hold those cap bits.

The 14 cap bits include filesystem read (FsReadCap), filesystem write (FsWriteCap), network bind (BindCap), and environment (EnvCap), among others. Read ooda://orientation/capabilities at runtime for the full table.

Examples

Call a tool with no args (Tier 0, no cap):

{"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"get_orientation","arguments":{}}}

Call a tool with required args:

{"jsonrpc":"2.0","id":4,"method":"tools/call","params":{"name":"read_board","arguments":{"name":"NORTHSTAR"}}}

Call a tool with optional args:

{"jsonrpc":"2.0","id":5,"method":"tools/call","params":{"name":"get_audit_log","arguments":{"tail":50}}}

Unknown tool returns:

{"error":"unknown tool: <name>"}

protocol.oot — Wire Protocol

File: ooda/mcp/docs/protocol.oot

The MCP server speaks JSON-RPC 2.0 over a Content-Length-framed stream transport (stdio, file, or Unix socket). The wire protocol is identical to LSP at the framing level, but the method namespace is MCP.

1. Framing

Each message is one HTTP-style header followed by a JSON body:

Content-Length: 87\r\n
\r\n
{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2024-11-05"}}

The Content-Length is the byte count of the JSON body. The header is mandatory on stdio and socket; the file transport also accepts raw JSON without the header.

A single stream may carry multiple messages. The receiver reads bytes until the header is complete, then reads exactly Content-Length more bytes for the body.

2. Envelope

Standard JSON-RPC 2.0 envelope for every request, response, and notification.

Request:

{"jsonrpc":"2.0","id":1,"method":"<name>","params":{...}}

Response (success):

{"jsonrpc":"2.0","id":1,"result":<value>}

Response (error):

{"jsonrpc":"2.0","id":1,"error":{"code":-32601,"message":"Method not found: <name>"}}

Notification (no response expected):

{"jsonrpc":"2.0","method":"<name>","params":{...}}

id may be a string or an integer. The server tracks seen id values to detect duplicates and rejects them with error -32600.

3. Standard error codes

CodeMeaning
-32600Invalid request (empty method, duplicate id)
-32601Method not found
-32602Invalid params (schema mismatch, missing required arg)
-32603Refused (cap revoked, session cancelled, URI outside roots)
-32604Tier denies method
-32605URI outside declared client roots

client_config.oot — Client Configuration

File: ooda/mcp/docs/client_config.oot

This doc covers how to wire the openOODA MCP server into MCP-aware clients. The server is a stdio binary; the client spawns it, sends framed JSON-RPC over stdin, and reads framed JSON-RPC from stdout.

1. Launching the server directly

The server is a standalone binary. Run it under the ooda toolchain:

ooda mcp                # stdio (default)
ooda mcp --stdio        # explicit stdio
ooda mcp --file <path>  # one-shot file mode
ooda mcp --socket <path> # Unix socket
ooda mcp-merge <file>   # inject into a client config

For MCP clients, the typical entry point is ooda mcp (stdio). The client must keep the process alive for the duration of the session and route every JSON-RPC envelope through stdin and stdout.

2. Claude Desktop

Claude Desktop reads its MCP server list from a JSON config file. The config is at claude_desktop_config.json (the path varies by OS):

OSPath
macOS~/Library/Application Support/Claude/claude_desktop_config.json
Linux~/.config/Claude/claude_desktop_config.json
Windows%APPDATA%\Claude\claude_desktop_config.json

Add the openOODA server under mcpServers:

{
  "mcpServers": {
    "openooda": {
      "command": "ooda",
      "args": ["mcp"]
    }
  }
}

The ooda binary must be on the PATH visible to Claude Desktop. If it is not, give the absolute path:

{
  "mcpServers": {
    "openooda": {
      "command": "/home/user/.oodaup/bin/ooda",
      "args": ["mcp"]
    }
  }
}

Restart Claude Desktop after editing the config. The openOODA server should appear in the tool list with 23 tools.

3. Cursor

Cursor reads MCP server config from ~/.cursor/mcp.json (or per-project .cursor/mcp.json):

{
  "mcpServers": {
    "openooda": {
      "command": "ooda",
      "args": ["mcp"]
    }
  }
}

Restart Cursor after editing the config.
