-- WHY WE ARE REBUILDING THE STACK: SYSTEMS + CRYPTO + AI --

01
ZERO AMBIENT AUTHORITY // Conservation of Authority

In conventional stacks, any library you import inherits the full permissions of the user running the process. In openOODA, authority is an explicit bearer capability governed by conservation of authority: permissions can never be minted out of thin air or widened, only explicitly delegated or monotonically attenuated.

02
FULL USE OF EVERY 64-BIT CPU CYCLE // 32 + 32 = 64 Architecture

The lower 32 bits encode all 32 root capabilities (13 Hardware + 19 Software/OS)—fitting natively in a single 32-lane GPU warp mask and seccomp-BPF accumulator. The upper 32 bits pack a 16-bit OODA Epoch (instant revocation), 8-bit Rights Mask (R/W/X/Delegate/Revoke), and 8-bit Scope Badge, validating WHAT and HOW/WHEN in a single 64-bit CPU cycle.

03
CRYPTOGRAPHIC PROVENANCE // Proof at Silicon Speed

We bring the mathematical guarantees of cryptographic systems—bearer capabilities, Merkle-DAG AST and build provenance, post-quantum warrants, and strict resource quotas—directly into the compiler and kernel ABI at nanosecond speed, with zero blockchain consensus overhead. ooda-compiler v0.17.2 enforces compile-time Secret zero-sink linear tracking with zeroize-on-drop, ooda prove (v2.18.2) verifies 16 mathematical, capability-law, and defense invariants (Noether, Curry-Howard, HoTT, Iris, CDCL, SMT, seL4, PAC, Shadow Stack), and ooda-runtime v5.19.0 pairs CSPRNG capability seeding with an oo_blackbox tamper-evident trap & audit ring.

04
DETERMINISTIC SUBSTRATE // Linux & Unix Heritage Reimagined

From systems programming and Landlock/IOMMU hardware isolation up to a capability microkernel, zero-root OS, and graphical desktop, openOODA pairs Unix composability with deterministic linear arenas, bounded resource quotas, and zero garbage-collection pauses.

05
AUTONOMOUS AI LOOPS // Closed-Loop OODA & Falsification

Built from day one for autonomous AI synthesis and verification. Every Observe–Orient–Decide–Act loop operates within strict capability budgets, backed by compile-time contracts and adversarial falsification rather than fragile prompt guardrails.

06
NATIVE MACHINE-CODE LOWERING // Zero External Toolchain Dependency

The self-hosting ooda-compiler lowers directly to native x86-64 ELF64 machine code without external C compilers or libc dependencies, verified end-to-end across hardware-isolated KVM microVMs. Hosted executables ship with PIE, Full RELRO, BIND_NOW, embedded .ooda.caps sections, Intel CET (IBT + SHSTK) and stack-clash hardening, Landlock plus openat2 path confinement, and deterministic --morph-seed function-order binary diversification, while ooda law enforces native Zero-Link, File-Law, and Shape conformance on every artifact.

HOW THE CONTRACT IS SCORED

Every cell is a directly observed fact, never an inference. VERSION is the repository’s latest semver release tag. ATTESTED compares that tag against the signed package index in @openOODA/catalog: SIGNED means the catalog attests this exact release with an audited digest, DRIFT means the repository has shipped ahead of the catalog. CAPS is the capability set the catalog records for the package — exactly the authority it may hold, never ambient. GATE is the CI verdict, and it applies to @openOODA only, the one organization that carries CI/CD gates; the other four ship without them, so those gates do not apply to their repositories. CONTRACT is the fail-closed verdict — a repository is credited only when every earlier gate passes: RELEASED → CITED → GREEN → SHIPPING → CLEAN.
